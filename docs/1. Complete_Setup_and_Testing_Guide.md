
## 1. Create a Python environment

```powershell
conda create -n veridian python=3.12 -y
conda activate veridian
python -m pip install -r requirements.txt
```

If you already have the environment, omit `conda create` and run the last two commands. Confirm with `python --version`.

## 2. Configure AWS IAM credentials

1. Sign in to the [AWS Console](https://console.aws.amazon.com/).
2. In **IAM → Users**, use a dedicated user for this demo; create an **Access key** under **Security credentials**.
3. Give the user the minimum permissions needed for `s3:PutObject`, `s3:GetObject` on the project bucket and Bedrock model invocation (`bedrock:InvokeModel`) for the chosen models. Other actions may be required depending on your AWS configuration.
4. Save the access key ID and secret key securely. Do not paste them into public chats or recordings.
5. Choose `us-east-1` for the examples below (or use the actual region where your models and bucket are available).

## 3. Configure Amazon Bedrock

1. Open [Amazon Bedrock](https://console.aws.amazon.com/bedrock/).
2. Select the configured AWS region.
3. Check that your account can invoke **Amazon Nova Lite** (`amazon.nova-lite-v1:0`) and **Amazon Titan Text Embeddings V2** (`amazon.titan-embed-text-v2:0`). Model availability and access steps vary by account and region.
4. Titan V2 will generate **1024-dimensional** embeddings in this project.

## 4. Create the S3 bucket and add the required CORS

1. Open [Amazon S3](https://console.aws.amazon.com/s3/).
2. Select **Create bucket**, choose a globally unique bucket name such as `veridian-documents-your-unique-suffix`, and use the configured AWS region.
3. Leave **Block all public access** enabled and enable encryption.
4. Open your bucket → **Permissions** → **Cross-origin resource sharing (CORS)** → **Edit**.
5. Paste this JSON and **Save changes**:

```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["PUT"],
    "AllowedOrigins": [
      "http://127.0.0.1:8000",
      "http://localhost:8000"
    ],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

**This step is required for the original browser-to-S3 upload version.** It fixed your earlier browser `Failed to fetch` error. Use the exact origin shown in your browser's address bar. If the frontend later runs at a different origin, add that origin as appropriate.

## 5. Configure Pinecone (automatic index creation)

1. Open [Pinecone Console](https://app.pinecone.io/).
2. Create an API key and copy it.
3. **Do not manually create an index.** The project creates `veridian-enterprise-ai-index` automatically on first indexing (or when running the optional check script).
4. The index configuration is **dense vectors, dimension 1024, cosine metric, serverless AWS `us-east-1`**.
5. Your account must allow index creation and have sufficient quota.

## 6. Configure Neon PostgreSQL

1. Open the [Neon Console](https://console.neon.tech/) and select the Veridian project.
2. Use **Connect** to copy the connection string for the `main` branch and `neondb` database, or link this repository with the Neon CLI.
3. Keep the connection string private. Set it as `DATABASE_URL` in the local `.env` file; `neon init` can populate it automatically for a linked project.
4. For deployment, configure `DATABASE_URL` as a protected GitHub Actions secret and pass it to the application container.

Example placeholder only:

```dotenv
DATABASE_URL=your_neon_postgresql_connection_string
```


## 8. Create the `.env` file

In the project root, copy `.env.example` to `.env`:

```powershell
Copy-Item .env.example .env
```

Edit `.env` to contain:

```dotenv
# AWS
AWS_ACCESS_KEY_ID=YOUR_AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY=YOUR_AWS_SECRET_ACCESS_KEY
AWS_SESSION_TOKEN=
AWS_REGION=us-east-1
S3_BUCKET=YOUR_PRIVATE_S3_BUCKET_NAME

# Neon PostgreSQL
DATABASE_URL=your_neon_postgresql_connection_string

# Pinecone (index created automatically)
PINECONE_API_KEY=YOUR_PINECONE_API_KEY
PINECONE_INDEX_NAME=veridian-enterprise-ai-index
PINECONE_CLOUD=aws
PINECONE_REGION=us-east-1
PINECONE_READY_TIMEOUT=180

# Bedrock
BEDROCK_EMBED_MODEL=amazon.titan-embed-text-v2:0
BEDROCK_CHAT_MODEL=amazon.nova-lite-v1:0
EMBED_DIM=1024

# App
HITL_ENABLED=true
MEMORY_TURNS=6
```

If you use temporary AWS credentials, set `AWS_SESSION_TOKEN`; otherwise leave it blank. **Do not set `PINECONE_INDEX_HOST` for this auto-create version.**

## 9. Initialize the database automatically

Run from the project root:

```powershell
python scripts/init_db.py
```

Expected: a success message confirming the PostgreSQL database and **five tables**: `documents`, `feedback`, `audit_events`, `approvals`, and `chat_messages`. The script is safe to rerun with the supplied schema.

If this fails, confirm the Neon endpoint is active, `DATABASE_URL` is current, and your local network can reach Neon.



## 10. Run the application

```powershell
uvicorn app.main:app --reload
```

Open these URLs in the browser:

- **App:** http://127.0.0.1:8000
- **API documentation:** http://127.0.0.1:8000/api/docs
- **Liveness:** http://127.0.0.1:8000/health/live
- **Database readiness:** http://127.0.0.1:8000/health/ready

Keep the VS Code terminal running. Use **Ctrl+C** to stop the server.
